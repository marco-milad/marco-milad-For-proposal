# Client intake: what to ask the user for before Phase 0

Send this checklist to the user at the very start, in their language. Present it as a short list, not a form. Say which items block the work and which only strengthen it. **Missing items never block the start.** Each gap becomes a labelled limitation or a discovery question in the proposal, so begin with what exists and record what is missing.

The "Unlocks" column is the reason to give the user when they ask why an item matters.

## Essential (the work stalls without these)

| Input | Unlocks |
|---|---|
| Company name and what it sells (B2B or B2C, products or services) | Positioning, keyword universe, page templates |
| Current website URL, or "none yet" | Chooses the **existing-site** or **greenfield** path in Track W |
| Product/service list: a catalog, company profile PDF or price-free product sheet | Product families, sitemap, keyword-per-page table |
| Target market: cities/countries, and the languages needed (AR, EN or both) | Local SEO, hreflang/URL policy, Arabic-first decisions |
| 3–5 named competitors | Competitor matrix, SERP sampling, anonymous patterns |
| The client's goal for the site: quote requests, online sales, calls/WhatsApp, brand visibility | Conversion paths, home-page sections, KPIs |
| Systems in use: ERP, CRM, shop platform, CMS (e.g. Odoo, Shopify, WordPress, Salesforce) | Platform decision, integration phases |
| Logo, brand colors/fonts, and real product photos | Prototype look; authentic imagery instead of stock |

## High value (each one makes the proposal stronger)

| Input | Unlocks | If missing |
|---|---|---|
| **Google Search Console + GA4 access** | Real traffic, query and ranking baselines; the only basis for any impact statement | No traffic or ranking numbers anywhere; KPIs say "baseline set in discovery" |
| **Ahrefs / Semrush (or similar) access** | Search volumes and keyword difficulty | Keywords prioritized by relevance only, labelled as such; no volume figures |
| Google Business Profile (link or access) | Local SEO audit, NAP consistency | Listed as a discovery item |
| Official social profile links | Social footprint, sameAs schema | Profiles found online stay "candidate" until confirmed |
| Company facts the client wants shown (founding year, certifications, authorized-dealer status, client counts) **with proof** | Trust sections, "in numbers" strip | Excluded from client copy until sourced |
| A past proposal the user likes | Format, tone, section order to match | Use the outlines in the track files |
| Who on the client side will edit content after launch | CMS choice, training needs | Becomes a discovery question |

## SEO plan extras

For any SEO work, also send the batch data request (D1–D13) in [seo-optimization-plan.md](seo-optimization-plan.md). The items that **block** a specific topic:
- the keyword map (keyword placement)
- Google Business Profile access (GBP changes)
- the official NAP (local SEO)
- hosting/CMS access (implementation only)

Everything else strengthens the plan. Missing items are named in the plan with the topic they would unlock.

## Greenfield extras (no website yet)

| Input | Unlocks |
|---|---|
| Domain: owned? which one? Any email on it? | URL plan, launch checklist |
| Content that already exists: about text, product descriptions, FAQs, brochures | Content plan; what must be written from scratch |
| Name, address, phone, working hours, map location (NAP) | Local SEO, Organization/LocalBusiness schema, contact page |
| Any social or marketplace presence (Facebook shop, Instagram, Amazon/Noon, directories) | What the new site must link to or replace; existing branded search footprint |

## Track M extras (integrated marketing proposal)

| Input | Unlocks |
|---|---|
| The team's strategy document (.docx) | The narrative spine, verbatim Arabic, change log |
| The agency's actual service list and names | Services execution model and profiles |
| The agency's genuine portfolio items (not placeholders) | Proof sections with real work |
| Strategy owner / who signs off | Gate approvals |

## Not needed

- **Prices, packages or budgets.** The proposal carries none.
- If the user knows the client's rough budget, take it as **private context** only. It can tilt the platform decision (e.g. toward improving the current platform). It never appears in the proposal.
